Accessibility

Accessibility is a design requirement, not an afterthought. Language Bridge aims to meet WCAG 2.1 AA and to keep every activity usable by every student.

What's in place

  • Keyboard operable. Choices, controls, mode toggles, and drawers are all reachable and operable with the keyboard, with a visible focus outline and a skip link.
  • Screen-reader friendly. Answer choices are real buttons with pressed state, feedback and progress use live regions, and target-language text is marked with its language so pronunciation is correct.
  • Color contrast. Text and interface colors meet WCAG AA; contrast is checked automatically on every build.
  • Feedback that teaches. No red-only signals, no loud error sounds, no punitive scoring — feedback explains why.
  • Reduced motion. Animations are minimized when the operating system requests it.
  • Right-to-left languages. Arabic and Urdu are supported with correct direction.
  • Paper. Every activity prints, so it works when devices or assistive tech are unavailable.

Still improving

A screen-reader walkthrough on real assistive technology and an automated audit are on the roadmap. If you hit a barrier, that is a bug we want to fix.
